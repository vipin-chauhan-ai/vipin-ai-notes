JWT Authentication Questions & Answers

Understand JWT authentication, token expiry, SECRET_KEY, and Bearer tokens in simple language.

16 Important JWT Questions Click any question to view its answer.
Q1 Why do we use SECRET_KEY?

SECRET_KEY is used to digitally sign the JWT token. It helps verify that the token has not been modified or tampered with.

Q2 What happens if someone knows our SECRET_KEY?

If an attacker knows the SECRET_KEY, they can create fake JWT tokens. Therefore, the key must always remain private and should never be exposed publicly.

Q3 Why do we use ALGORITHM = "HS256"?

HS256 is the hashing algorithm used to sign and verify JWT tokens. It helps ensure the integrity of the token.

Q4 Why do we set ACCESS_TOKEN_EXPIRE_MINUTES?

It defines how long the JWT token remains valid. After its expiration time, the token becomes invalid and the user must log in again.

Q5 Why do we create create_access_token()?

This function generates a JWT token by adding user information and an expiration time, then digitally signing it using the SECRET_KEY.

Q6 Why is the data parameter a dictionary?

A JWT payload can contain multiple pieces of information (claims), such as email, user ID, role, and expiration time. A dictionary stores these as key-value pairs.

{
  "sub": "vipin@gmail.com",
  "role": "admin",
  "user_id": 1
}
Q7 Why do we use data.copy()?

data.copy() creates a copy of the original dictionary. This lets us modify the copied data without changing the original payload.

Q8 Why do we use datetime.utcnow()?

It returns the current UTC time, which is used as the reference time when calculating the JWT token's expiration.

Q9 Why do we use timedelta()?

timedelta() adds a specific duration, such as minutes, hours, or days, to the current time. It is used to calculate the token's expiration time.

Q10 Why do we add "exp" to the payload?

The exp claim stores the JWT token's expiration time. Once the token expires, it becomes invalid and cannot be used for authentication.

Q11 What does to_encode.update({"exp": expire}) do?

It adds the expiration time (exp) to the JWT payload before generating the token.

Before:
{
  "sub": "vipin@gmail.com"
}

After:
{
  "sub": "vipin@gmail.com",
  "exp": "2026-08-06 01:30:00"
}
Q12 What does jwt.encode() do?

jwt.encode() converts the payload into a digitally signed JWT token using the SECRET_KEY and the selected algorithm.

Q13 What does jwt.encode() return?

It returns an encoded JWT token as a string.

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Q14 Why do we return the encoded JWT token?

The client stores this token and sends it with future requests to access protected APIs.

Q15 Why don't we return only "Login Successful"?

A success message cannot be used for authentication. The client needs the JWT token to access protected routes.

Q16 Why do we return token_type = "bearer"?

It tells the client that the JWT token must be sent in the HTTP Authorization header using the Bearer scheme.
