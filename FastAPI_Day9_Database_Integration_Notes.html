FastAPI Day 9 - Database Integration (SQLAlchemy + SQLite)

1. What is SQLite?
Answer
SQLite is a lightweight, file-based relational database. It stores the entire database, including tables and records, inside a single .db file. It does not require a separate database server.
Hindi:
SQLite ek lightweight, file-based relational database hai jo poora database ek .db file me store karta hai. Iske liye alag server ki zarurat nahi hoti.
2. What is SQLAlchemy?
Answer
SQLAlchemy is a Python ORM (Object Relational Mapper) library that allows developers to interact with databases using Python objects instead of writing raw SQL queries.
Hindi:
SQLAlchemy ek Python ORM library hai jo Python objects ke through database operations karne ki suvidha deti hai.

4. What is ORM?
Answer
ORM (Object Relational Mapper) is a technique that maps programming language objects to database tables. It allows developers to perform database operations without writing raw SQL.
Hindi:
ORM ek technique hai jo Python objects ko database tables se map karti hai.
5. Why do we use ORM?
Answer
Reduces raw SQL writing.
Improves code readability.
Supports multiple databases.
Makes code easier to maintain.
6. What is DATABASE_URL?
Answer
DATABASE_URL is a connection string that tells SQLAlchemy which database to connect to and how to connect.
Example:
DATABASE_URL = "sqlite:///students.db"
7. What is create_engine()?
Answer
create_engine() creates and manages the database connection between SQLAlchemy and the database.
Example:
engine = create_engine(DATABASE_URL)
8. Does create_engine() create database tables?
Answer
No.
create_engine() only prepares the database connection.
Database tables are created later using:
Base.metadata.create_all(bind=engine)
9. What is Session?
Answer
Session is used to perform database operations such as:
Create
Read
Update
Delete
10. What is sessionmaker()?
Answer
sessionmaker() is a factory that creates Session objects.
These Session objects are then used to perform CRUD operations.
11. Difference between Engine and Session?
Answer
Engine Session
Creates and manages the database connection. Performs CRUD operations (Create, Read, Update, Delete).
Does not execute CRUD operations directly. Executes database operations using the Engine.
Created once and reused throughout the application. Created when needed and used during database transactions.
Acts as the connection manager. Acts as the communication layer between Python objects and the database.
12. Why can't we use Engine directly?
Answer
Engine is responsible for creating and managing the database connection.
CRUD operations are performed through a Session object.
13. What is autocommit=False?
Answer
It means SQLAlchemy will not automatically save changes.
The developer must explicitly call:
db.commit()
to permanently save data.
14. What happens if the application crashes before db.commit()?
Answer
The data will not be permanently saved because the transaction has not been committed.
15. What is autoflush=False?
Answer
It prevents SQLAlchemy from automatically flushing pending changes before executing queries.
It gives full control to the developer.

17. What is declarative_base()?
Answer
declarative_base() creates the base class for all ORM models.
Any class inheriting from Base is treated as a database table.
Example:
class Student(Base):


18. What is Base.metadata.create_all(bind=engine)?
Answer
It creates all database tables defined by ORM models.
If the SQLite database file does not exist, it is created automatically.


19. Can SQLAlchemy work with MySQL and PostgreSQL?
Answer
Yes.
SQLAlchemy supports multiple databases including:
SQLite
MySQL
PostgreSQL
Oracle
SQL Server
Usually, only the database connection URL and the required database driver need to be changed.


20. If we switch from SQLite to PostgreSQL, do we rewrite the whole application?
Answer
No.
Generally, we only change the DATABASE_URL and install the appropriate PostgreSQL driver. Most of the SQLAlchemy ORM code remains the same.
