📘 Day 10 - SQLAlchemy Models (Part 1)

Questions & Answers

Q1. Why do we inherit Base?
Base is the parent class for all SQLAlchemy ORM models. Any class that inherits from Base is treated as a database table.
Q2. What happens if we don't inherit from Base?
The class becomes a normal Python class. SQLAlchemy will not recognize it as an ORM model, so no database table will be created.
Q3. What is __tablename__?
__tablename__ specifies the name of the database table that SQLAlchemy should create. Example: __tablename__ = "students"
Q4. Can the class name and table name be different?
Yes. Example: class Student(Base): __tablename__ = "college_students" Class Name: Student Table Name: college_students
Q5. What is primary_key=True?
It marks a column as the Primary Key. A primary key uniquely identifies each record in the table.
Q6. What happens if we don't define a Primary Key?
SQLAlchemy cannot uniquely identify records. Every ORM model should have at least one primary key; otherwise SQLAlchemy raises an error while mapping the model.

Q10. What does Base.metadata.create_all(bind=engine) do?
It creates all database tables defined by SQLAlchemy ORM models. If the SQLite database file does not exist, it creates it automatically.
Q11. What happens if we remove Base.metadata.create_all(bind=engine)?
The application may start successfully, but SQLAlchemy will not create the database tables. When we try to perform CRUD operations, an error occurs because the required table does not exist.
Q12. Why do we write import models?
import models loads all ORM models into memory. This registers them with Base. Without importing the models, Base.metadata.create_all() does not know which tables to create.
Q13. What happens if we remove import models?
The application starts successfully, but no database tables are created because SQLAlchemy does not know about the ORM models.
