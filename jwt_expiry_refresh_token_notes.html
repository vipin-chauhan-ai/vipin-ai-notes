JWT Token Expiry & Refresh Token

Simple FastAPI notes for Access Token expiry and Refresh Token flow.

Click any topic to open it. First understand Token Expiry, then learn how a Refresh Token creates a new Access Token.

1. What is JWT Token Expiry?

Token expiry means a JWT token works only for a limited time. After that time, the server rejects it.

Login → Access Token created → Token expires after the configured time
ACCESS_TOKEN_EXPIRE_MINUTES = 30

In this example, the Access Token is valid for 30 minutes.

2. Why do we use Token Expiry?
  • A stolen token cannot be used forever.
  • It improves API security.
  • The user must get a new valid token after expiry.
3. How is expiry added to a JWT?

The exp claim stores the expiry date and time inside the JWT payload.

expire = datetime.utcnow() + timedelta(
    minutes=ACCESS_TOKEN_EXPIRE_MINUTES
)

to_encode.update({"exp": expire})
4. What happens when the token expires?

The protected API returns:

{
  "detail": "Token has expired"
}

Status code: 401 Unauthorized

5. What is a Refresh Token?

A Refresh Token is used to get a new Access Token after the Access Token expires.

Access Token  → Short life, for example 30 minutes
Refresh Token → Long life, for example 7 days
6. Why do we need a Refresh Token?

Without a Refresh Token, the user must login again after every Access Token expiry.

Access Token expires → Client sends Refresh Token → Server verifies Refresh Token → Server returns a new Access Token → User continues without logging in again
7. Refresh Token expiry time 
REFRESH_TOKEN_EXPIRE_DAYS = 7

This means the Refresh Token can be used for 7 days. After that, the user must login again.

8. Complete Access Token + Refresh Token Flow
  1. User logs in.
  2. Server returns an Access Token and a Refresh Token.
  3. Client calls /profile using the Access Token.
  4. Access Token expires.
  5. Client sends Refresh Token to /refresh-token.
  6. Server verifies it and returns a new Access Token.
  7. Client calls /profile again with the new Access Token.
9. Access Token and Refresh Token must be different
/profile endpoint → Only Access Token accepted /refresh-token endpoint → Only Refresh Token accepted

Add token type in the payload:

# Access Token
{
  "sub": "user@email.com",
  "type": "access"
}

# Refresh Token
{
  "sub": "user@email.com",
  "type": "refresh"
}
10. Important JWT Security Rule

Never store sensitive data inside a JWT payload. A JWT payload can be decoded, so it is not a safe place for secrets.

  • Password
  • OTP
  • PIN
  • Secret key
  • Bank details
