FastAPI SQLAlchemy Session, Dependency Injection & Database Flow

BaseModel is provided by Pydantic and is used to validate incoming request data before it reaches the database.

Whenever a client sends JSON data to a FastAPI API, Pydantic checks whether the data matches the required structure and data types.

If the request contains invalid data, FastAPI automatically returns a 422 Validation Error.

Example:

{

"name": "Vipin",

"age": 30,

"course": "Python"

}

This request is valid because the data types match the schema.

schemas.py is used to keep all Pydantic models in one place.

These models are responsible for validating API requests and responses.

Keeping schemas separate from database models makes the project clean, maintainable, and production-ready.

StudentCreate is a Pydantic model that defines the structure of the incoming request.

class StudentCreate(BaseModel):

name: str

age: int

course: str

Whenever a client sends data, FastAPI converts that JSON into a StudentCreate object after successful validation.

Although both classes are important, they serve completely different purposes.

Base (SQLAlchemy)

Used to create database tables.

Used inside models.py.

Creates ORM models.

Performs database mapping.

BaseModel (Pydantic)

Used for request and response validation.

Used inside schemas.py.

Validates client data.

Converts JSON into Python objects.

A production FastAPI application uses both because they have different responsibilities.

BaseModel validates the client's request before it reaches the database.

Base defines how data should be stored inside the database.

This separation makes the application secure, clean, and easier to maintain.

Both Engine and Session are part of SQLAlchemy but have different responsibilities.

Engine

The Engine creates and manages the database connection.

It does not perform CRUD operations.

Session

The Session performs CRUD operations such as Insert, Update, Delete, and Select.

It also manages database transactions using commit(), rollback(), and close().

SessionLocal is created using sessionmaker().

It is not an actual database session.

Instead, it acts as a Session Factory, which creates new Session objects whenever required.

Example:

SessionLocal = sessionmaker(

autocommit=False,

autoflush=False,

bind=engine

)

Whenever we write:

db = SessionLocal()

A new database Session object is created.

This Session object is responsible for performing CRUD operations.

Every request gets its own Session object.

yield temporarily pauses the function.

Unlike return, it does not immediately end the function.

This allows FastAPI to use the database session first and execute cleanup code later.

Depends() is FastAPI's Dependency Injection system.

It automatically provides required objects like database sessions to API functions.

Example:

db: Session = Depends(get_db)

FastAPI automatically:

Calls get_db()

Creates Session

Passes Session to API

Closes Session after request completion

After request validation, we create an ORM object.

new_student = models.Student(

name=student.name,

age=student.age,

course=student.course

)

Here,

student

is a Pydantic Object.

new_student

is a SQLAlchemy Object.

Only SQLAlchemy objects can be stored in the database.

Pydantic objects validate incoming data.

SQLAlchemy objects interact with the database.

The application first validates the request using Pydantic and then converts it into a SQLAlchemy object before saving.

db.add(new_student)

db.add() adds the SQLAlchemy object to the current Session.

At this stage, the object is not permanently stored inside the database.

It only becomes part of the current transaction.

db.commit()

db.commit() permanently saves all pending changes from the Session into the database.

Without calling commit(), no data is permanently stored.

If the application crashes before commit(), all pending changes are lost.

db.refresh(new_student)

db.refresh() reloads the object from the database.

It updates the object with the latest values generated by the database, such as the automatically generated primary key (id).

Example:

Before Refresh

id = None

After Refresh

id = 1
