Day 6 - Request Model & Response Model

1. What is a Request Model?
Answer
A Request Model is used to receive and validate data sent by the client before processing it.
2. What is a Response Model?
Answer
A Response Model is used to filter and control the data returned to the client while hiding sensitive information.
3. Why should we use Response Models?
To avoid exposing sensitive information like passwords, tokens, OTPs, emails, or internal fields.
4. Difference between Request Model and Response Model?

Difference between Request Model and Response Model

Request Model Response Model
Used to receive data from the client. Used to send data back to the client.
Validates incoming request data. Filters and controls outgoing response data.
Converts JSON into a Python object. Converts a Python object into the required JSON response.
Prevents invalid data from entering the application. Prevents sensitive or unnecessary data from being exposed.
Connected through the function parameter. Connected through the response_model parameter in the decorator.
Used before business logic is executed. Used after business logic is executed.
5. Which Status Code should be returned after successful POST?
201 Created
6. Why does FastAPI return 422?
Because the client sends invalid data that does not match the validation rules defined in the Pydantic model.
7. Real-Life Example
Registration API
Client Request
{
"name":"Vipin",
"email":"vipin@gmail.com",
"password":"123456"
}
Database stores all fields.
Client Response
{
"name":"Vipin",
"email":"vipin@gmail.com"
}
Password is hidden using the Response Model.
8. Key Points
Request Model receives and validates client data.
Response Model filters response data.
Never expose passwords or sensitive information.
Use 200 OK for successful GET requests.
Use 201 Created for successful POST requests.
422 Validation Error occurs when request data does not match the expected validation rules.
