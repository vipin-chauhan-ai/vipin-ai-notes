User Files

User model, validation schema and API router—explained through simple revision accordions.

01

user_model.py

This file defines the users table and the data stored for each registered user.

User registration→User model→users table
Why create a separate User model?

JWT Authentication is designed for users. A separate User model stores the information required for registration and login.

Purpose of __tablename__ = "users"

It tells SQLAlchemy to create and use a database table named users.

Purpose of primary_key=True

It uniquely identifies every user record in the database.

Purpose of index=True

It creates a database index that makes searching faster. It is useful for email because login searches users by email.

Purpose of unique=True for email

It prevents duplicate email addresses and ensures that every user has one unique login identity.

Why is password stored as String?

Passwords are stored as hashed text, not as numbers. Therefore the password column uses the String data type.

Why store age and course?

They are additional user details which can be used by the application when required.

If unique=True is removed from email

Duplicate email addresses will be allowed, which can cause problems during user login.

If index=True is removed from email

The application will still work, but searching by email may become slower as the database grows.

02

user_schemas.py

This file validates registration data received from the client before it reaches the database.

Validation flow: Client data → Pydantic schema → Validation → API logic → Database
What is UserCreate?

UserCreate is a Pydantic model used to validate user registration data received from the client.

Why inherit from BaseModel?

BaseModel provides automatic data validation, parsing and serialization.

Why use Field()?

Field() applies validation rules such as required fields, minimum length, maximum length and numeric limits.

Meaning of ... (three dots)

It means the field is required and cannot be omitted.

Why use EmailStr instead of str?

EmailStr automatically checks whether the input is a valid email address.

Why use min_length for password?

It ensures the password has the required minimum length before FastAPI accepts the request.

Why password hashing is not done inside the schema

The schema only validates data. Password hashing is business logic, so it belongs in the API or authentication layer.

If email format is invalid

FastAPI automatically returns a 422 Validation Error.

If a required field is missing

FastAPI returns a 422 Validation Error because the request does not satisfy the schema.

03

user_router.py

This file keeps user and authentication API routes separate from the main application.

APIRouter()→User routes→app.include_router(router)
Why use APIRouter?

APIRouter organizes related API endpoints into separate modules, making a project cleaner and easier to maintain.

Why not create FastAPI() inside user_router.py?

Only one main FastAPI() application should exist. Other files use APIRouter() and register their routes with the main application.

Purpose of router = APIRouter()

It creates a router object that holds all authentication-related routes.

Why use Depends()?

Depends() uses Dependency Injection. It automatically provides required dependencies such as a database session.

Purpose of db_get()

It creates a database session, provides it to the API and closes it after the request is complete.

Why use yield instead of return?

yield keeps the database session available during the request and ensures it is properly closed in the finally block.

Why close the database session?

Closing the session releases database resources and prevents connection leaks.

Why not write all APIs inside main.py?

Putting every API in main.py makes the project difficult to manage. Separate router files keep code modular and maintainable.

Purpose of SessionLocal()

SessionLocal() creates a new database session for each request.
