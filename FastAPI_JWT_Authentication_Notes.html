02

JWT ?

JWT means JSON Web Token. After a user logs in, the API provides a token. The user then sends that token to access protected APIs instead of sending a username and password with every request.

HeaderContains token metadata, such as algorithm and token type.
PayloadContains non-sensitive user information, also called claims.
SignatureVerifies that the token has not been changed.
Header.Payload.Signature
03

Header Example

{ "alg": "HS256", "typ": "JWT" }
  • alg means the algorithm used to sign the token.
  • typ means the token type.
04

What Can Go Inside the Payload?

Payload should contain only non-sensitive information.

User ID→Username→Role
Never put sensitive information in a JWT payload: password, OTP, PIN and secret key should never be included.
05

Password Security

Passwords must never be stored as plain text. If a database is compromised, attackers can read all plain-text passwords immediately.

Store passwords in hashed form. Hashing protects the original password value in the database.

06

Quick Revision

Authentication
It verifies a user's identity: who are you?
Authorization
It decides the permissions available to an authenticated user: what can you access?
JWT purpose
It lets a user use a secure token for protected APIs after login, rather than resending credentials every time.
JWT structure
A JWT has three parts: Header, Payload and Signature.
Payload safety rule
Keep only non-sensitive claims such as user ID, username and role. Never include passwords, OTPs, PINs or secret keys.
Password storage rule
Passwords should always be stored in hashed form, never as plain text.
